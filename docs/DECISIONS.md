# Decisions

Baseline ported from `nuxt-3-template` (UI conventions, tokens), Revcube's newer API layer
(services, forms), and Archer (`archer-frontend-nuxt3`: presenter pattern, agent guidance in
`AGENTS.md`). On 2026-10-05 the data layer was refactored: the axios services → Route Handlers →
repositories stack and the Prisma 8 RC were replaced by a server-only DAL, Server Actions, Zod DTOs,
Prisma 7.10 and Better Auth (rows below reflect the current state). Each row: what the source setup
used → what this project uses → why.

`(site)` pages are now request-time rendered because the layout reads the session for the NavBar.

## shadcn reset

The UI uses stock Radix/New York primitives reinstalled through the official shadcn CLI.
`components.json` points to `styles/global.css`; the previous palette, HSL bridge, and primitive
SCSS overrides were removed. The CLI's style registry supplies the shared base styles, and the
neutral token values come from the [official neutral registry](https://ui.shadcn.com/r/colors/neutral.json).
Only Prettier formatting is applied to generated components, so CLI updates do not erase app logic.

Labels/errors and loading behavior live in separate application wrappers. `lib/utils.ts` stays
CLI-owned; `getInitials` lives in its own file. The generated components use the CLI's `cn` package.

Theme support follows the [official Next.js guide](https://ui.shadcn.com/docs/dark-mode/next):
`next-themes`, a class-based provider with system default and transition suppression, and a
light/dark/system menu. The stock Sonner component reads the same provider. The root HTML tag has
`suppressHydrationWarning` because the provider sets its theme class before hydration.

References: [installation](https://ui.shadcn.com/docs/installation/next),
[CLI](https://ui.shadcn.com/docs/cli), [theming](https://ui.shadcn.com/docs/theming).

## Stack choices

| Area                    | Nuxt template / Revcube                                                     | Next template                                                                                                                              | Why                                                                                                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework               | Nuxt 4                                                                      | Next.js 16 App Router                                                                                                                      | Latest stable; App Router is the current default.                                                                                                                                   |
| Package manager         | yarn 1 / bun                                                                | bun                                                                                                                                        | Fast installs; Revcube already uses bun. Scripts still run on Node.                                                                                                                 |
| Bundler                 | Vite                                                                        | Turbopack (Next default)                                                                                                                   | Default in Next 16; no custom loaders needed.                                                                                                                                       |
| Pages                   | `pages/**` + `script.ts` + `styles.scss`                                    | `app/**/page.tsx` + optional `view.tsx` (client) + `styles.module.scss`                                                                    | Server page owns metadata/data; client view owns interactivity.                                                                                                                     |
| Layouts                 | `layouts/Default`, `layouts/minimal`                                        | Route groups `app/(site)` and `app/(minimal)`                                                                                              | Route-group layouts are the App Router equivalent.                                                                                                                                  |
| Catch-all 404           | `pages/[...slug].vue`                                                       | `app/not-found.tsx`                                                                                                                        | Built-in not-found convention.                                                                                                                                                      |
| Route paths             | `/Posts`                                                                    | `/posts`                                                                                                                                   | Lowercase URLs are conventional.                                                                                                                                                    |
| Scoped styles           | `<style scoped lang="scss">`                                                | CSS Modules `styles.module.scss`                                                                                                           | Native Next support, component-scoped by default.                                                                                                                                   |
| Design tokens           | `assets/palette.scss` → `variables.scss` → CSS vars                         | Official shadcn neutral tokens in `styles/global.css`, shared by primitives and CSS Modules                                                | Removes the custom palette and token overrides; both themes use the official shadcn values.                                                                                         |
| SCSS breakpoints        | Vite `additionalData`                                                       | `sassOptions.additionalData` in `next.config.ts`                                                                                           | Same `$breakpoint-*` variables in every module.                                                                                                                                     |
| Font                    | Google Fonts `<link>`                                                       | `next/font/google` Inter (`--font-inter`)                                                                                                  | Self-hosted, no layout shift.                                                                                                                                                       |
| UI primitives           | shadcn-vue + reka-ui                                                        | shadcn/ui (new-york) + Radix UI, in `components/SCN`                                                                                       | Direct React counterpart. Flat shadcn file layout kept so `shadcn add` keeps working.                                                                                               |
| Tailwind                | v3 + `tailwind.config.ts`                                                   | v4 CSS-first, official global base layer; utilities in stock `components/SCN` primitives                                                   | Standard shadcn setup without a separate Tailwind token layer.                                                                                                                      |
| Animations              | tailwindcss-animate                                                         | tw-animate-css                                                                                                                             | shadcn's v4 replacement.                                                                                                                                                            |
| Icons                   | lucide-vue-next                                                             | lucide-react                                                                                                                               | Same icon family.                                                                                                                                                                   |
| Toasts                  | vue-sonner + `$toast`                                                       | sonner `toast`                                                                                                                             | Same library family.                                                                                                                                                                |
| Global state            | Pinia                                                                       | None (Zustand removed)                                                                                                                     | The viewer is read on the server; add a store when real cross-component client state appears.                                                                                       |
| Server state / fetching | `useAsyncData` / Revcube `useApiData`                                       | Server Components read the DAL; client fetches only via facades                                                                            | No HTTP round trip to our own handlers; TanStack Query had no remaining use.                                                                                                        |
| Presenters              | Revcube class presenters (`new XPresenter(response)`)                       | Archer-style `presentX(dto) => ({ ...dto, overrides })` functions, only where a view needs an override                                     | Types are the contract; presenters only reshape. Plain objects also cross the Server→Client boundary.                                                                               |
| DTO types               | Hand-written `*Response` interfaces                                         | Zod schemas in `lib/dto`, types via `z.infer`; per-operation variants                                                                      | Runtime validation and types from one source; client- and server-safe. Drift from the DB fails to compile where the DAL maps rows.                                                  |
| JSON key casing         | `snake_case` (Rails/Revcube)                                                | camelCase, matching the Prisma model fields                                                                                                | DTOs mirror the model field names; no renamed copy.                                                                                                                                 |
| Backend                 | jsonplaceholder / Rails                                                     | Server-only DAL (`lib/data`) + Server Actions; one Route Handler for client reads                                                          | The baseline owns its data layer; Route Handlers exist only where a client must fetch.                                                                                              |
| ORM / DB                | —                                                                           | Prisma ORM 7.10.0 (stable) + PostgreSQL 16                                                                                                 | Prisma 8 was an RC with a pinned toolchain override; Better Auth's official adapter supports 5–7.                                                                                   |
| Prisma shape            | Prisma 7 `schema.prisma` + `@prisma/client`                                 | `schema.prisma`, `prisma-client` generator to `generated/`, `@prisma/adapter-pg`, `DateTime` → `Date`                                      | Prisma 7's default generator; client regenerated on `postinstall`; `importFileExtension = "ts"` so the seed runs on plain Node.                                                     |
| Server data in RSC      | `useAsyncData` on server                                                    | DAL functions called directly                                                                                                              | Next discourages Server Components fetching their own Route Handlers.                                                                                                               |
| Auth                    | Token cookie read by JS, global middleware                                  | Better Auth 1.7 email/password, official Prisma adapter, DB sessions, `nextCookies`; `proxy.ts` optimistic guard                           | Auth.js is in maintenance under the Better Auth team; Better Auth is the recommended path.                                                                                          |
| Auth hardening          | —                                                                           | Better Auth `disabledPaths` for `/sign-up/email` and `/update-user`; in-memory rate limit on the sign-in/sign-up actions (production only) | The HTTP router would bypass our validation, and its limiter does not cover Server Actions. In-memory is per process: use Redis or Better Auth's database storage across instances. |
| Session refresh         | —                                                                           | Sessions (7 days) refresh only through Server Actions or the auth route                                                                    | Server Components cannot set cookies, so a user who only browses is signed out when the session expires.                                                                            |
| Roles                   | —                                                                           | `role` enum column (`user`/`admin`) as a Better Auth additional field; owner-or-admin on posts                                             | Smallest real example of record-level rules.                                                                                                                                        |
| Writes                  | —                                                                           | Server Actions with plain Zod `safeParse` (`parseInput`), no next-safe-action                                                              | Fewer moving parts. Accepted: build-specific action IDs, POST-only, sequential, not callable by non-UI clients; auth in the DAL mitigates a forgotten check.                        |
| Data access             | —                                                                           | `lib/data` DAL, `server-only`, the only Prisma importer (lint-enforced)                                                                    | One place for queries, mapping, and auth (Next's data-security guide).                                                                                                              |
| Errors                  | —                                                                           | Typed DAL errors → `ActionResult` / HTTP 401-403-404-422 / redirect or `notFound()`                                                        | Each caller translates once; forms map `fieldErrors`.                                                                                                                               |
| Pagination              | Rails-style `Listing`                                                       | `Page<T> = { items, page, perPage, totalItems, totalPages }`                                                                               | Replaces the Rails-style `Listing`.                                                                                                                                                 |
| Forms                   | VeeValidate + `@vee-validate/zod` + Zod                                     | React Hook Form + `@hookform/resolvers` + Zod 4                                                                                            | React counterpart; same schema-first flow.                                                                                                                                          |
| Field markup            | shadcn-vue `FormField`/`FormItem`                                           | Application Input/Textarea wrappers own `label`, `required`, `error`; stock primitives stay unchanged                                      | Template rule: no generic FormField wrapper.                                                                                                                                        |
| Runtime config          | `runtimeConfig.public`                                                      | `NEXT_PUBLIC_*` via `lib/env.ts`                                                                                                           | Next's env convention.                                                                                                                                                              |
| Auto-imports            | Nuxt auto-imports                                                           | Explicit imports, `@/` alias                                                                                                               | React/Next has no auto-import.                                                                                                                                                      |
| Tests                   | vitest stub                                                                 | Vitest + Testing Library + jsdom; server tests on a real test DB                                                                           | Fast unit tests, real integration for handlers.                                                                                                                                     |
| Docker                  | Node app containers                                                         | `docker-compose.yml` with PostgreSQL only                                                                                                  | Deployment image deferred to a later iteration.                                                                                                                                     |
| Deferred                | vuedraggable, FileUpload, Tabs, Modal, TableSimple, AppAvatar, date pickers | Not ported yet                                                                                                                             | Ported later, on demand, using the same conventions.                                                                                                                                |
