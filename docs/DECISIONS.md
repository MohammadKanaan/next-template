# Decisions

What this project uses and why. How each choice is applied is in `AGENTS.md` and the code.

## Stack

- **Next.js 16 App Router, Turbopack:** the current stable default.
- **bun as package manager, scripts on Node:** fast installs, a boring runtime.
- **shadcn/ui on Base UI (`base-vega`):** shadcn defaults new projects to Base UI and `new-york` has
  no Base UI variant, so on 2026-10-12 the Radix primitives were re-added with
  `shadcn add --overwrite`. Generated files only get Prettier, so CLI updates never erase app logic;
  behaviour lives in application wrappers. Links styled as buttons are `ButtonLink`, because Base
  UI's Button forces `role="button"`. Theme follows the
  [official Next.js guide](https://ui.shadcn.com/docs/dark-mode/next).
- **SCSS CSS Modules with the stock shadcn neutral tokens; Tailwind only in `components/SCN`:**
  component-scoped styles, one theme source, no custom palette.
- **No global client state:** the viewer is read on the server. Add a store when real
  cross-component client state appears.
- **Server Components read the DAL directly:** Next discourages pages fetching their own Route
  Handlers, and no client query library is needed.
- **Zod DTOs in `lib/dto`, types from `z.infer`:** runtime validation and types from one source, safe
  on client and server; drift from the database fails to compile where the DAL maps rows.
- **Presenters as `({ ...dto, overrides })` functions:** types are the contract, presenters only
  reshape, and plain objects cross the Server → Client boundary.

## Data

- **Prisma ORM 7.10 (`prisma-client` generator, `@prisma/adapter-pg`) on PostgreSQL 18, one `init`
  migration:** Prisma 7's default generator, regenerated on `postinstall`; the seed runs on plain
  Node. A template's migration history starts with the project.
- **UUIDv7 ids generated by Prisma Client (Better Auth with `generateId: 'uuid'`):** a malformed id
  becomes a Zod failure instead of a PostgreSQL error, and v7 sorts by creation time (lists still
  order by `createdAt, id`: v7 is only millisecond-ordered).
- **A `users_role_valid` CHECK, hand-written in the init migration:** keeps the admin plugin's
  free-text role honest.
- **UTC database session (`-c timezone=UTC`):** the adapter treats `timestamptz` as wall-clock time
  in the session zone, so a server elsewhere would store shifted instants.
- **`lib/data` DAL, the only Prisma importer (lint-enforced):** one place for queries, mapping and
  auth, per Next's data-security guide.
- **Input validation in the DAL (`parseInput`):** the one layer every caller shares, so it cannot be
  skipped. Accepted cost: a Route Handler parses twice.
- **Pure policies per resource (`lib/data/policies`) behind `authorize` / `permissionsFor`:**
  testable per viewer without a database. CASL or ZenStack is the next step if rules become
  data-driven.
- **Typed DAL errors, translated once per caller:** to `ActionResult`, an HTTP status, or a
  redirect / `notFound()`.
- **Numbered pages, `page` capped at 1000:** fits tables and filtered lists.
- **Redis as the only cache, with versioned tags (`INCR`) and TTLs, fail-open:** a version bump
  makes every old entry unreachable at once; cached JSON is re-parsed with the DTO schema.
- **Rendering per request, no `cacheComponents`:** Cache Components would add a second cache Redis
  invalidation cannot reach. In exchange a page is one async function and `redirect()` /
  `notFound()` answer with real statuses. Given up: the prerendered static shell and default
  streaming.

## Auth

- **Better Auth 1.7 (email and password, Prisma adapter, DB sessions, `nextCookies`):** Auth.js is
  in maintenance under the Better Auth team, which recommends Better Auth.
- **`disabledPaths` on every Better Auth route whose rules live in an action or the DAL:** the HTTP
  router would bypass our validation and per-account limits (its own limiter is per process and
  trusts a spoofable address). A `hooks.before` guard stops a change-email link opened without the
  account's session from signing the opener in.
- **Redis rate limits (fixed window, `MULTI INCR` + `PEXPIRE NX`), production only, fail-open:**
  limits hold across instances. An outage must not lock everyone out of signing in, an accepted
  security trade-off.
- **Better Auth's `admin` plugin, wrapped by `lib/data/admin.ts`:** the plugin owns what is easy to
  get wrong (a ban revokes sessions and blocks sign-in, impersonation keeps the admin session
  aside). Wrapping it keeps one way in and adds our rules (admins are peers: never your own account,
  never another admin).
- **A separate `(admin)` route group with shadcn's sidebar:** keeps the site chrome off the
  dashboard and makes a new section a nav item and a route.
- **Sessions (7 days) refresh only through actions or the auth route:** Server Components cannot set
  cookies, so a user who only browses is signed out when the session expires.
- **Better Auth's `changeEmail` and `deleteUser`; profile edits and sessions through our own DAL:**
  reuses its flows and tokens while keeping our username and password rules in one place.
- **Optional Google sign-in (on when both variables are set):** the login most requirements ask for,
  free when unset. The round trip has never been run here (no credentials).

## Writes and API

- **Server Actions with no wrapper library:** fewer moving parts. Accepted: build-specific action
  ids, POST only, sequential; the DAL covers a forgotten check.
- **React Hook Form + Zod 4, `'use no memo'` in every RHF file:** schema-first forms on the DTO
  schemas. RHF 7 is not React-Compiler-safe (`register()` must run on every render).
- **React Compiler, no hand-written memoization:** nothing depends on memoization for correctness.
- **`const` arrow functions everywhere:** one form for everything.
- **REST over the same DAL (`app/api/v1/posts`), session-cookie auth, JSON bodies only:** an HTTP API
  costs nothing when it routes through the DAL; the JSON content type plus `SameSite=Lax` is the
  CSRF guard. The public reads run searched, counted queries, so they are limited where they are
  reached (120 a minute per endpoint and address); flooding the pages is the reverse proxy's job.
- **An OpenAPI 3.1 spec generated from the DTO schemas (`zod-openapi`), rendered by Scalar:** it
  cannot drift from what the handlers decode, and it imports no DAL, so building it never touches
  the database.

## Infrastructure

- **pg-boss 12 on the existing PostgreSQL:** no new infrastructure, retries and cron built in.
  BullMQ would give Redis a second job (and eviction risk); a hosted queue adds a dependency.
- **A separate worker process (`tsx`):** long-running work stays out of the web process, which only
  enqueues.
- **`lib/data/maintenance.ts` without auth, importable from `jobs/**` only:** jobs have no viewer,
  and the lint fence keeps pages and actions away from it.
- **Resend through the `send-email` job, plain templates:** sending is slow and can fail, so it
  retries in a job, and enqueueing without awaiting hides whether an account exists. Plain
  templates render anywhere; React Email's renderer needs `react-dom/server`, which the React
  Server layer refuses.
- **Cloudflare R2 with presigned PUTs and no uploads table:** no egress fees and no MinIO container.
  R2 has no presigned POST, so the exact size is signed and the object re-checked on attach. The
  object key says whose it is and what for; a table to sweep unattached objects cost two enums, a
  status machine and a job for a few kilobytes of orphans, which the ticket limit (10 an hour)
  bounds instead.
- **`serverEnv()`, Zod-validated on first use:** `next build` and tests that never touch Redis or
  Resend work without those variables; one error lists every problem.
- **`GET /api/health` (database and Redis, ok/fail only):** a probe must be current, unauthenticated
  and leak no error text.
- **pino with module child loggers and redaction:** structured JSON, and auth flows carry live links
  that must never reach logs.
- **A nonce-based CSP from `proxy.ts`:** the only policy used to be `frame-ancestors 'none'`, so an
  XSS bug ran whatever it injected. Styles stay `'unsafe-inline'` because Base UI positions popovers
  with `style` attributes, which cannot run code.
- **One origin (`siteUrl()`) for every absolute URL; robots and sitemap built per request:** links in
  metadata and emails agree, `next build` stays free of the database, and the sitemap never lags.
  `noindex` lives on the page because a crawler reads it only where `robots.txt` allows the fetch.
- **Docker: PostgreSQL and Redis in compose; an `app` profile for `migrate`, `web` and `worker` from
  one image:** no `output: 'standalone'`, because the worker runs TypeScript through `tsx` and
  migrations need the Prisma CLI. Not yet run end to end.

## Tests and docs

- **Vitest, Testing Library, jsdom; server tests on a real database and Redis:** a test must be able
  to fail for a real bug. No tautologies, mock-only assertions, tests of library behaviour, pins of
  static copy, or duplicates of a stronger test.
- **The code is the documentation:** the area guides restated the code and went stale, so they were
  deleted. `AGENTS.md` keeps the rules the code cannot show; prose remains only for setup, the R2
  bucket and patterns that are not implemented.

## Deferred

- **Organizations:** every query would gain a tenant key and every policy a membership check, a
  design decision for the project that needs it.
- **API keys:** the REST endpoints use the session cookie.
- **End-to-end browser tests:** the suite stops at Vitest.
- **A last-admin guard on account deletion:** an admin cannot change their own role, but the last
  admin can still delete their account.
